# Disrust для Windows

<img src="assets/avatar.png" alt="Аватар Disrust" width="112">

Оболочка на Rust для веб-версии Discord. Открывает `https://discord.com/login` в отдельном тёмном окне через установленный в Windows Microsoft Edge WebView2. Друзья, серверы, каналы, переписки, вложения и поиск используют интерфейс и инфраструктуру Discord.

[Скачать ZIP для Windows x64](https://github.com/SpeedyEzKv/disrust/releases/download/v0.1.1/Disrust-windows-x64.zip) · [Релиз 0.1.1](https://github.com/SpeedyEzKv/disrust/releases/tag/v0.1.1)

Это экспериментальный сторонний проект. Запуск формы входа нестабилен на проверенной машине. Сценарии после входа предстоит проверить.

## Запуск

1. Распакуй ZIP и открой `dist\Disrust.exe` на Windows x64. Если WebView2 отсутствует, установи [Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/#download).
2. Войди на странице Discord внутри окна. При необходимости пройди проверку Discord самостоятельно. Тему чатов можно изменить в настройках Discord.
3. Для голосовой комнаты дай Discord разрешение на микрофон, когда Windows или WebView2 его запросит. Для демонстрации экрана проверь, что Discord показывает кнопку трансляции и окно выбора источника. Если функции нет в оболочке, пользуйся ею в поддерживаемом браузере или официальном приложении.

Внешние ссылки, открытые пользователем, передаются в браузер Windows. Оболочка до двух раз повторяет HTTPS-загрузку, если после старта страница входа осталась пустой. Для ручного обновления используй Ctrl+R, F5 или пункт обновления в контекстном меню WebView2. Сессия сохраняется в отдельном профиле `%LOCALAPPDATA%\Disrust\Profile`. Профиль содержит данные веб-сессии. Для выхода из учётной записи воспользуйся настройками Discord. Приложение использует хранилище WebView2 и не обрабатывает пароль или токены в Rust.

## Архитектура и ограничения

По [документации OAuth2](https://docs.discord.com/developers/topics/oauth2#shared-resources) обычное приложение может получать идентификатор профиля и базовый список серверов. Информация о существующих личных чатах и голос от имени пользователя ограничены партнёрским доступом. `messages.read` относится к локальному RPC, который опирается на запущенный клиент Discord. Social SDK умеет работать с друзьями, сообщениями и голосом, но предназначен для игр, лобби и связанных каналов. Бот действует под отдельной учётной записью. [Возможности Social SDK](https://docs.discord.com/developers/discord-social-sdk/core-concepts/communication-features).

Slint и egui подходят для оригинального интерфейса Windows на Rust. Оба варианта требуют поддерживаемого источника данных и отдельной реализации чатов и мультимедиа. Сочетание Tao и Wry использует нативное окно Windows и установленный Chromium-движок WebView2. Оно сохраняет штатный веб-вход, раскладку и существующий аккаунт. Сам интерфейс Discord работает в браузерном движке. [Slint](https://github.com/slint-ui/slint) · [egui](https://github.com/emilk/egui) · [Wry](https://github.com/tauri-apps/wry).

Rust-код открывает только точный HTTPS-адрес `discord.com` внутри основного окна и не предоставляет сайту нативные объекты или канал сообщений. Оболочка сохраняет штатные проверки HTTPS, SmartScreen и диалоги системных разрешений. Она не модифицирует код Discord и не автоматизирует аккаунт. Запрет Discord на автоматизацию обычных аккаунтов вне OAuth2 и Bot API может приводить к блокировке аккаунта. [Условия Discord](https://discord.com/terms) · [Правила об автоматизации аккаунтов](https://support.discord.com/hc/en-us/articles/115002192352-Automated-User-Accounts-Self-Bots).

Голос, видеозвонки и демонстрация экрана зависят от WebView2, настроек сайта и разрешений канала. Discord описывает работу браузерного голосового чата и трансляций, но не подтверждает совместимость этой оболочки. Системные уведомления зависят от WebView2 и Discord. Интеграции официального приложения, такие как игровой оверлей и глобальные горячие клавиши, сюда не входят. [Голос и трансляции в Discord](https://support.discord.com/hc/en-us/articles/33030151293079-Discord-Voice-Video-Streaming-Guide) · [API WebView2](https://learn.microsoft.com/microsoft-edge/webview2/concepts/overview-features-apis).

`rust-anything` не понадобился, поскольку оболочка написана с нуля, а исходников клиента Discord для переноса нет.

## Сборка и проверка

Потребуются Rust MSVC, Visual Studio Build Tools с компонентами C++ и WebView2 Runtime.

```powershell
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo build --release --locked
.\tools\measure.ps1 -Runs 3
.\tools\measure.ps1 -Runs 1 -Offline
.\tools\package.ps1
```

Замеры создают отдельный профиль для каждого прогона и скрытое окно. Время хоста отсчитывается от входа в `main`. Время готовности формы проверяется с шагом в одну секунду. Память — сумма Private Bytes оболочки и дерева WebView2. CPU замеряется на интервале в 5 секунд и указывается в процентах от одного логического ядра. Отзывчивость — задержка доставки события в основной цикл окна, без учёта отрисовки и задержки сети. Это замеры страницы без входа, а не тест прокрутки чата или звонка.

## Результаты на этой машине

Windows x64, сборка 26200. Форматирование, Clippy, тест ограничения навигации и сборка release прошли. Локальная страница в WebView2 отобразилась. Удалённая форма Discord отобразилась в двух из трёх прогонов со свежим профилем.

| Сценарий | Старт хоста | Форма входа | Private Bytes хоста / всего | CPU на интервале после загрузки | Цикл окна p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Локальная страница | 562 мс | — | 4,63 / 142,46 МиБ | 0,0% | 0,19 мс |
| Discord, прогон 1 | 475 мс | 25,5 с | 6,22 / 462,43 МиБ | 18,5% | 0,24 мс |
| Discord, прогон 2 | 474 мс | не появилась | 5,93 / 482,41 МиБ | 55,2% | 1,15 мс |
| Discord, прогон 3 | 583 мс | 16,6 с | 4,98 / 507,74 МиБ | 0,0% | 0,32 мс |

Основной документ Discord вернул HTTP 200 во всех трёх прогонах. Некоторые запросы к ресурсам страницы оборвались с `ERR_CERT_VERIFIER_CHANGED`, а повторная загрузка помогла не во всех случаях. Если страница остаётся пустой, попробуй обновить её обычным способом. Проверки сертификатов не отключались. [Коды ошибок Chromium](https://chromium.googlesource.com/chromium/src/+/main/net/base/net_error_list.h).

Форма входа и QR-код были доступны, но вход с реальным аккаунтом, сообщения, вложения, уведомления, голос и демонстрация экрана не проверялись. Диагностика подтвердила наличие браузерных API для микрофона и захвата экрана, а не успешный разговор или трансляцию. Сопоставимых замеров с официальным клиентом нет, поэтому ускорение не подтверждено.
